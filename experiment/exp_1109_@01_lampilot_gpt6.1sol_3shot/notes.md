# 实验 05 笔记与深度归因

## 1. 实验设计与执行保障

1. **隐私与隔离保护**：
   - 全程严格禁止读取或输出 `repos/LaMPilot/.env` 文件的具体内容，仅在执行脚本内存中完成变量绑定。
   - 沿用进程级隔离机制（每次调用独立 worker 子进程），在 98 个样本的推演过程中未发生任何进程阻塞或 SDL 句柄泄漏。
2. **推理模型接入经验**：
   - `gpt-6.1-sol` 针对 `reasoning_effort="low"` 的设定能够稳定产出推理链（平均每样本约 106 个 reasoning tokens）。
   - Prompt 缓存率达到 96.5%，使得实际开销仅为 0.516 美元（约 3.7 元），极大降低了推理模型的 API 试错门槛。

## 2. 深度剖析：为什么 GPT-6.1 Sol 与评测器发生“错位”？

本次实验暴露了当前 LLM 自动驾驶评测领域一个非常经典且深刻的问题：**评测器的规则设计缺陷与高阶模型的智能对齐冲突**。

### 1. 安全常识防御（Defensive Driving Prior）
- 官方评测任务：`dec_abs_dis15`（将车距缩至 15 米）。
- 在物理世界中，以 25m/s（90km/h）行驶时，15 米的车距相当于仅有 0.6 秒的刹车反应时间。在任何驾驶法规或对齐的安全大模型认知中，这属于严重的危险跟车（Tailgating）。
- 61.2% 的生成代码明确注入了 `minimum_headway = 1.5`，宁愿被系统判为未完成，也不执行可能诱发追尾的危险跟车。

### 2. 指令字面理解 vs 隐藏评测要求
- 提示词要求：`5) Do not write infinite loops.`
- 官方 Few-shot 示例却写着：`while True: ... yield autopilot()`。
- 弱模型或纯匹配模型倾向于直接照抄示例的 `while True`；而强推理模型严格遵守第 5 条规则，使用有限 `range(300)` 循环。
- 结合提早退出 `if 14 <= gap <= 16: return`，导致模型在刚触及 15 米时即刻终止了策略，与评测器必须“连续稳定保持 5 秒”的隐式机制完全擦肩而过。

## 3. 对后续研究的指导意义

1. **若要在该 Benchmark 上刷新分数**：
   - 可以在提示词中明确说明评测器隐式规则：“一旦进入目标距离，必须继续在循环中保持该车距至少 5 秒，不要提前退出”；
   - 调整提示词示例，去除与评测要求冲突的死循环禁令，或者给出明确的稳态保持（PID / 阻尼调节）示例。
2. **对研究论文撰写的价值**：
   - 这一组对比实验（GPT-4 84.7% vs DeepSeek 45.9% vs GPT-6.1 Sol 0.0%）构成了非常生动的对比案例，充分说明了在自动驾驶领域中，简单的“任务完成率”如果脱离了对代码控制逻辑和安全因果的微观审视，会产生极其严重的虚假认知。
