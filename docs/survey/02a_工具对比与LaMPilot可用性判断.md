### 1.2 DR 独有、核实为真且相关的条目

在三个包里都找到了，所以 **Pro 不是 DR 的严格超集**：

- P1：Hybrid-Driving（AAAI 2025，免训练，基本确定用 Highway-env）、REINS（NeurIPS 2026，仓库里有 highway-v0 等 4 个场景和 `evaluate.py`）、ADRD、TR-C 2026。
- P2：Intention-Drive（arXiv:2512.12302，开环评测，表 1 直接测了 GPT-5.2、Gemini 3 Pro 和智能体框架）、BEVDriver（IROS 2025）。
- P3：中国公路学会征求意见稿第 4.3.2 条（语音指令进入或退出辅助驾驶、变更目的地等，直接回答 Q2）、Think at 5 Hz, Act at 20 Hz、Senna-2、理想“月使用率 80%”。

### 1.3 结论与以后的分工

| 任务类型 | 用法 |
| --- | --- |
| 广度调研（占位图、现状地图） | **两个都跑，取并集**。Pro 作为主报告；DR 很快、边际成本低，专门用来补召回。只出现在 DR 里的条目，逐条回原文核验后才能入库 |
| 做死检查（P4） | **两个都跑**。漏掉一篇前人工作是这一步最大的风险，召回比精度更重要 |
| 产品事实、中文一手来源、数字核对（P3 这类） | **以 Pro 为准**。DR 关于“某厂商不支持某功能”这类否定性结论不能直接采信 |

## 2. LaMPilot 的现状事实

### 2.1 论文数字与第三方使用

- 论文 Table 3 的 0-shot 和 3-shot 两列与 n=98 吻合，即只覆盖 `dec_abs_dis15` 这一个任务配置；Human Feedback 一列与 n≈110 吻合（12 个 Demo 样本 + 98 个样本）。见 `人类认知和术语对齐/LaMPilot测试划分与论文结果.md`。
- **两份 P1 报告和子任务的独立检索，都没有找到第三方在 LaMPilot-Bench 上报告新结果，也没有找到扩展它的工作。** LLM4AD 综述 Table IV 的数字与 Table 3 完全一致，是同一组实验的重复报告。
- 官方仓库 2026-01 仍在维护，README 的演示已换成 GPT-5.2。

### 2.2 本地实验与代码事实（Claude 已核对）

| 事实 | 依据 |
| --- | --- |
| 评测器要求车距进入目标值 ±30% 区间后**连续保持 5 秒**，60 秒内做不到就判失败 | `evaluator/acc.py` 中的 `ACCEvalbyDistance`（`time_duration = 5`，`dis_tol = 0.3 × 目标距离`） |
| **提示词没有告诉模型这条成功判据** | `prompts/cg_template_fs.txt` |
| 提示词规则第 5 条写“Do not write infinite loops”，但 3-shot 示例本身用的就是 `while True` | 同上 |
| 示例 1 的代码里，`front = detect_front_vehicle_in(...)` 之后接的是 `if front_vehicle:`，引用了一个未定义的变量 | 同上 |
| 策略函数一旦 `return`（`StopIteration`），车辆就交回 autopilot 行驶，不再受策略控制 | `dt/vehicle_dt.py` 中的 `act()` |
| DeepSeek 98/98 照抄了 `while True`，完成率 45.9%，0 碰撞，53 个失败全部是超时 | 实验 03 |
| GPT-6.1 Sol 0/98 用 `while True`，50/98 显式设了最小时距下限（`minimum_headway`），完成率 0%，0 碰撞 | 实验 05 的 policy 文件（Claude 统计） |
| 在 25 m/s 车速下，15 m 车距对应约 0.6 s 时距 | 简单计算 |

**由此可知**：“DeepSeek 和 GPT-6.1 达不到 GPT-4 的水平”这个判断**不成立**，至少不能这么下结论。在这 98 个样本上，完成率衡量的不只是模型能力，还混入了三个因素：
1. 模型是否猜中了一条没写出来的成功判据；
2. 模型是否照抄带缺陷的示例；
3. 模型面对一条接近不安全的指令时，选择执行还是选择保守。

GPT-6.1 得 0% 主要来自第 3 点和第 1 点。

## 3. Claude 的判断

### 3.1 LaMPilot 还能不能用

要先区分“复现”的两种含义：

| 含义 | 能否做到 | 是否必要 |
| --- | --- | --- |
| 用 GPT-4 复现出 84.7% 这个数字 | 不能，GPT-4 已下线 | **不必要**。方法论要求的是“可靠锚点”，不是“与原文数字一致” |
| 在固定、公开的样本划分上，用当前模型完整跑通官方流程，得到稳定、可解释的数字 | **已经做到**（实验 03、05） | 这才是 04 阶段要的锚点 |

所以 LaMPilot 并没有因为无法复现而失效。真正的问题是：**它原任务的“完成率”能不能作为有意义的指标**，而第 2.2 节的事实说明，至少在 `dec_abs_dis15` 上不能直接用。

**它的不可替代性取决于研究问题是否以“人类指令”为核心：**
- **如果是**：LaMPilot 在 Highway-env 上基本不可替代。可以把它当作平台和样本来源，不必以原论文的完成率为目标。
- **如果不是**：比如转向“免训练 LLM 逐步决策”，那 DiLu（ICLR 2024，代码完整）才是 Highway-env 上的标准锚点，SanDRA 次之。

这是 02 阶段要做的选择，应该在填问题卡时由你决定，不是现在换 baseline 的理由。

> 关于第 2.2 节的现象（隐含判据、示例缺陷、安全与指令冲突），它们是**事实素材**，可以写进问题卡的“问题前提”或证据链第②环（常规完成率看不出模型是否听懂了指令）。要不要据此定题，由你判断。Claude 不在这里把它包装成研究问题。

### 3.2 平台探针要不要做

**要做，但要先改一下。** 原定目的是判断“原任务是否接近饱和”；现在已知在 `dec_abs_dis15` 上没饱和，但失败多半是评测和提示词造成的伪影。另外，这 98 个样本只覆盖了 32 个任务配置中的 1 个，其他 5 个任务类别（路口、变道、超车、靠边停车、速度控制）的情况完全未知。

建议在计划文档第 6 节的基础上调整：
- 样本保持不变：6 个任务类别分层抽样，每类 16 个，共 96 个，排除 Demo 样本。
- 条件：(1) IDM / autopilot（不读指令）；(2) DeepSeek 3-shot（官方提示词）；(3) GPT-6.1 3-shot（官方提示词）；(4) **诊断条件**：在官方提示词末尾加一句该任务评测器的成功判据（例如“进入目标区间后需连续保持 5 秒”），其余不变。
- 条件 (4) 不是方法，只用来区分“模型做不到”和“模型不知道要做到什么”。只在 DeepSeek 上跑即可。
- 对每个失败样本，除原定的四类失败标签外，再记录一项：策略是否提前 `return`，或是否主动设了安全下限。
- 预算：约 4 × 96 × 3K ≈ 120 万 tokens，按实验 03、05 的单价估算，总计不到 10 元。

事先约定的解读规则在原有三条之外再加一条：如果条件 (4) 比条件 (2) 明显提升，说明原任务的完成率主要在测“是否猜中隐含判据”。这个结论本身就是证据链第②环的素材。

### 3.3 Human Feedback 版本要不要做

**现在不做。** 原因有三：
- 它需要人在终端逐条交互、依赖 OpenAI embeddings，还要手动处理 12 个 Demo 样本（见实验 03 笔记）；
- 它是一个方法变体，对 02 阶段“选哪个问题”没有帮助；
- 如果最后锁定 LaMPilot 作为 baseline，再在 04 阶段决定要不要实现它。

### 3.4 问题卡

问题卡不必等探针做完再动笔。“提升空间或诊断价值的证据”这一栏可以先空着，其余栏目现在就能写。建议顺序：

1. Claude 把 P1–P3 的 Pro 和 DR 结果合并成 `02a_现状地图.md` 和 `02a_证据链.md`，只收已核验的条目（约 1 天）。
2. 同时跑改过的平台探针（半天）。
3. 你写 1–3 张问题卡，第一个要决定的问题是“研究是否以人类指令为核心”。
4. 对候选问题用 P4 做死检查，Pro 和 DR 都跑。

**不需要新一轮广泛调研。** P1 已经把 Highway-env 上的可替代锚点查清楚了（第 2.3 节）。下一次检索应该是候选问题出来后的 P4 做死检查，模板已在 `docs/prompts/02b_P4_做死检查模板.md`。
