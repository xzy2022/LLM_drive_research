
## 研究过程的概念明确

|         | 说明                                    | 如何获得                                                                |
| ------- | ------------------------------------- | ------------------------------------------------------------------- |
| 研究领域    |                                       | 通过学术访谈、听 Talk 和个人基础知识储备，感知学科风向。没有这个条件可能就只能看组里的项目、导师的安排，然后自己结合 AI 选择 |
| 任务目标    | 整个领域的公共常识和终极愿景                        | 无需调研，人人都懂。例如语义分割提高精度、轻量化加速                                          |
| 领域专家上下文 | 围绕既定方向，搜集高相关度的前沿论文，为大模型填充该细分领域的专业知识背景 | 文献调研中构建                                                             |
| `研究问题`  | 具体技术矛盾或核心症结                           | 靠 `领域专家上下文` 确定                                                      |
| 核心 Idea | 针对研究问题的机制给出的可行的解法                     | 靠 `领域专家上下文` 和复现的 baseline 发散，根据可行性排序筛选                              |
| 科学假设    | 因果假设和实验前的预期和设计                        | 在有一个比较可行的 Idea 的基础上，主要依靠人设计                                         |

## 研究阶段划分

| 阶段               | 理想情况       | 做法                                                                                                                                                     |
| ---------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 01_ 研究领域确定       | 最好全靠人      | 通过学术访谈、听 Talk 和个人基础知识储备，感知学科风向，圈定一个有生命力的大方向（确立宏观研究意义）                                                                                                  |
| 02_ 研究问题确定       | 大多数都靠人     | 在大方向下定位一个尚未被彻底解决的具体痛点，明确“我要在什么场景（Setting）下解决什么问题”                                                                                                      |
| 03_ 文献调研         | 人定标准，AI 执行 | 围绕研究问题，让 AI 检索该方向的前沿论文与开源代码。这一步同时完成三件事：<br>构建 `领域专家上下文`；<br>确认该问题未被前人做死（确立微观学术意义）；<br>结合自身资源与项目开源情况筛出可跑通的 Baseline（确立硬件与工程可行性）                         |
| 04_baseline 复现   | 人和 AI 协作   | 人负责准备计算资源，并在环帮助配置环境；然后和 ai 一起完成 baseline 复现                                                                                                            |
| 05_Idea 设计与筛选    | 人与 AI 深度协同 | 基于跑通的 Baseline 和调研文献，提出解决该问题的核心架构或算法机制。此时需要综合评估Idea 的方法可行性：<br>1. 技术是否可行；<br>2. Baseline 兼容性如何；<br>3. 实现复杂度是否可控。<br>“Gemini 发散 + Codex 评审 + Claude 拍板” |
| 06_ 实验设定         | 高度靠人的实验思维  | 在写代码前制定严格的“实验契约”，明确核心假设、成功/失败信号以及实验预期，防止跑出结果后看图编故事。                                                                                                    |
| 07_Trick 调优与代码实现 | 高比例交由 AI   | 在固定的环境、Baseline 和实验设定下，通过具体的代码修改、局部模块微调和消融实验去验证 Idea 并刷高指标。<br>几乎可以全链路交给 Claude Code + Codex 解决                                                        |
| 08_ 分析结果         |            |                                                                                                                                                        |
| 09_ 写论文          |            |                                                                                                                                                        |

说明：
1. Idea 实现了发现不 work 就得跳回去重新想，结果有苗头但方法有问题就得跳回去重新改。一篇论文定稿前这个循环往往要重复多轮。一个 Idea 直接拿到好结果并不是最好的科研，甚至这些初始 Idea 本身都不重要，真正有价值且属于你的是在实验探索中对结果的深度分析与多轮修正。
2. 关于可行性、风险问题：
	- 前置可行性过滤：`04_baseline 复现` 先确保 Baseline 已成功复现作为可靠锚点(哪怕有开源代码，复现成功率也并不高，经常遇到环境报错或结果对不上)，baseline 不能复现就放弃并更换。`05_Idea 设计与筛选` 让 gpt/codex 对 10 个备选 Idea 进行严格打分，直接淘汰（kill）难以落地的方案。 
	- AI 时代提 Idea 成本极低，且高度依赖 Baseline 锚点：绝大多数科研不是从零写代码，而是基于某个 Baseline 展开的。只要选中的是近期顶会的热门 Baseline，在其代码框架下总能找到改进切入点；而且一旦 Baseline 跑通、锚点确立，`05_Idea 设计与筛选` 阶段让 Gemini 结合文献积累一次性发散生成 10 个与该 Baseline 兼容的 Idea 只需要几分钟。
	- 设定明确的失败信号：`06_ 实验设定` 阶段进行详细的实验设计，防止 ai 一直发散跑偏，得不到真正有用的结论或者一直无法终止。
