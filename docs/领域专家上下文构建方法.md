# 领域专家上下文：是什么，怎么构建

> 本文回答这个问题：`docs/AI+科研方法.md` 和小红书原文都说文献调研的本质是“构建领域专家上下文”，那具体应该放进去什么？Deep Research 报告能不能直接当作领域专家上下文？

## 1. 结论

**Deep Research 报告不能直接作为领域专家上下文。它的定位是“检索索引 + 选文依据”。**
领域专家上下文应该是一个**围绕某个已确定研究问题、由论文原文片段组成、事实经过核验**的“上下文包”。

## 2. 为什么报告不能直接用

| 问题 | 在本项目中的实例 |
| --- | --- |
| 是二手转述，错误会被下游当作事实继承 | 第一轮 Deep Research 写“pyrobosim 已合入 110 个任务”（实际只加了一行链接），还写 LE-Nav 代码 404（实际可以访问）。这些错误如果进入 idea 阶段，会直接导致 Baseline 选错 |
| 夹带了模型自己的判断和修辞 | 报告中的“科学问题提炼”和“零样本 GPT-4o 存在显著鸿沟”属于阐释，而原表显示两者只差 1–6 个百分点 |
| **夹带了 idea，会污染 05 阶段** | 报告第 5 节已经写了 3 个“候选研究问题”。小红书原文强调，发散 idea 的模型应该“只拿到文献调研的结果和 baseline 信息，从一个干净的起点去想”。把带 idea 的报告喂进去，会让后续发散被锚定在这 3 个方向上 |
| 广而不深，稀释注意力 | 20 篇论文、8 个检索角度、约 10 万字符，大部分与最终研究问题无关 |

## 3. 上下文包应该包含什么（按层级）

小红书原文的做法是“能拿到 LaTeX/Markdown 就喂原文；调研阶段读摘要和引言就够了”。本项目在此基础上，按与研究问题的距离分层，各层放入的内容不同：

| 层级 | 放什么 | 来源 | 篇数 |
| --- | --- | --- | --- |
| L0 问题定义 | Setting、资源约束、研究问题（02 阶段的产出） | 人写 | 1 份 |
| L1 锚点论文 | Baseline 论文的**摘要 + 引言 + 方法 + 实验设置 + 关键结果表原文** | arXiv LaTeX 源码或 HTML 转 Markdown | 1–2 篇 |
| L2 核心论文 | **摘要 + 引言**（必要时加关键结果表） | 同上 | 5–8 篇 |
| L3 外围索引 | 每篇一行：标题 / 发表处 / 一句话 setting / 代码状态（已核验） | Claude 根据核验结果整理 | 10–20 条 |
| L4 复现记录 | 04 阶段跑出来的真实数字、环境路径、踩过的坑 | 复现后写入 | 1 份 |

**不放进上下文包的内容**：Deep Research 的“候选研究问题”“科学问题包装”“风险判断”等模型观点，以及被否决过的 idea。

## 4. 制作流程

1. **Deep Research（广度 + 精读）** → 得到候选论文清单和初步判断。
2. **Claude 核验** → 用 arXiv、GitHub、Crossref API 和全文检索核对论文、仓库和数字，剔除错误项，确定 L1/L2/L3 的归属。
3. **Claude 抽取原文** → 下载 arXiv 源码（或 HTML），只截取所需章节，转成 Markdown，存到 `context/<研究问题>/papers/<arxiv_id>.md`。原文内容不做改写。
4. **人工审阅** → 检查 L0 的问题定义和 L1/L2 的选篇。
5. **按阶段取用**：
   - 05 阶段让 Gemini 发散 idea：给 L0 + L1 + L2 + L4，**不给**调研报告；
   - Codex 逐个评审 idea：只给 L1（Baseline 论文）+ 当前这一个 idea；
   - 新开 Claude 会话做决策：给 L0 + L3 + idea card。

## 5. 时机

上下文包必须在研究问题**收窄之后**再做。目前（2026-11-06）第一轮调研是撒网式的，产出的是“选题地图”，还不是领域专家上下文；要等第二轮聚焦调研完成、方向确定以后，才开始制作上下文包。
