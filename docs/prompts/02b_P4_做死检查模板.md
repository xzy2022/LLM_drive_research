# 02b · P4 · 候选问题做死检查（模板）

> **用途**：候选问题卡写出来以后，逐个检查它是否已被前人做过。产出用于证据链第⑤环，见 `docs/02_问题定位调研计划.md` 第 7.3 节。
> **填写**：只填 Setting 和问题陈述，不要写“我们认为与已有工作的差异”，让工具独立去找最接近的工作，避免被我们的判断锚定。
> **用法**：每个候选问题单独新开一次对话。最好两个工具都跑。
> **保存**：`docs/survey/02b_P4_<候选名>_gpt.md`、`docs/survey/02b_P4_<候选名>_gemini.md`。

```text
你是自动驾驶与大模型方向的资深审稿人。下面是一个候选研究问题。请检查它是否已经被前人做过，或者离被做过只差一小步。真实性优先：宁可少列，也不要列出无法核实的内容。

## 候选问题
- Setting：【平台 / 输入 / 使用的大模型 / 执行器 / 是否训练】
- 问题陈述：【一句话】

## 需要回答的问题
Q1 列出与该问题最接近的 5–10 篇工作（含预印本），逐篇说明：覆盖了问题的哪一部分，没有覆盖哪一部分。
Q2 是否存在已经完整做过这个问题的工作？如果有，给出出处。
Q3 审稿人最可能提出的 3 个质疑是什么（例如新颖性、平台局限、对比是否公平）？每个质疑都要有文献依据。
Q4 列出你用过的检索词和来源，以及无法访问的内容。

## 真实性要求
- 每篇工作都要给出：完整英文标题、第一作者、年份、发表状态（已发表 / 已接收 / 仅预印本）、arXiv ID 或 DOI。
- 关键判断标注【原文】或【推断】。
- 不要提出改进方案或新的 idea。
```
